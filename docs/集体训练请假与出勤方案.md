# 集体训练请假与出勤方案

状态：2026-11-22 已部署并完成线上数据库迁移。

## 操作与规则

- 查看入口位于“球队”和“每周训练计划”。队长或管理员逐次添加集体训练，填写北京时间的开始、结束时间和地点；一周可有多次。自 2026-11-23 起，队员改在账号页“我的请假”提交、修改、取消训练请假并查看本人记录，训练详情页只保留跳转链接和队长出勤管理。
- 每次训练按开始时间向前计算 72 小时。截止时刻提交仍算按时；逾期仍可提交，但会标记为逾期。修改已有请假原因不改变提交时刻；取消后重新提交，以新提交时刻判断。
- 队长或管理员在训练结束后逐人确认实际出勤。确认出勤显示“已出勤”；确认未出勤且有按时有效请假显示“请假缺席”；确认未出勤而没有按时有效请假显示“旷训”。未确认时不自动判定旷训，也不自动扣积分。
- 普通队员仅能查看本人的请假与出勤、以及汇总人数；队长和管理员可查看队员名单、请假理由并确认出勤。预计到场按当前所有活跃账号减去有效请假人数估算，包含活跃管理员账号，并非实际出勤或独立报名人数。队员本人提交与取消请假的页面已迁移到账号页，见 [账号页训练与比赛请假变更方案](账号页训练与比赛请假变更方案.md)。
- 开始时间在出现有效请假后不能直接修改；需要改期时可取消本场并新建，原请假不会自动转移。当前不会自动给队员发送通知。

## 数据库变更

在现有 SQLite 数据库新增三张表，不修改个人体能打卡、积分或既有训练计划：

1. `training_sessions`：训练名称、开始和结束时间、地点、创建者和取消状态。
2. `training_leave_requests`：每人每场的请假理由、提交时间、提交时截止时间、按时或逾期及有效状态。
3. `training_attendance`：队长确认的实际出勤、确认人和确认时间。旷训由出勤与有效请假状态共同计算，不预先写入。

上线不导入既往训练，也不会把旧记录认定为旷训。队长需从上线后自行创建训练。

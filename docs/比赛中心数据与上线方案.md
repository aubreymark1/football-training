# 比赛中心：数据与上线方案

此方案用于现有 Flask + SQLite 网站。比赛中心已于 2026-11-22 部署，线上数据库已完成迁移。

## 数据结构

- `matches`：赛事、轮次、时间、球队、地点、状态、比分、战报及进球和助攻文字记录。已结束比赛必须填双方比分。
- `match_managers`：由管理员明确选择账号授予的比赛维护权限。现有管理员也能维护；普通成员不能维护。马煜需要在上线后由管理员按账号确认并授权，不按姓名自动授权。
- `match_players`：每场参赛球员及首发／替补，可关联网站账号，也可手动填写未注册球员。
- `match_ratings`：每人对同一球员保存一份 1.0–10.0 分评分及可选文字评论，可修改；按实际平均分选出 MVP，最高分相同则并列，评分持续开放。无评分时不显示 MVP。
- `match_reflections`、`match_reflection_likes`、`match_reflection_comments`：每场可发表多条文字反思，反思可附一张不超过 7 MB 的图片；队员可以点赞和评论。作者可编辑文字、删除自己的反思；比赛维护者和管理员可删除反思及评论。

图片保存在数据库中，随现有 SQLite 备份；此项会增加数据库和备份体积。现阶段反思编辑只修改文字，图片需删除原反思后重新发布才能更换。

## 赛程迁移

首次启动创建新表时，将现有 `league_schedule.py` 中的 10 场赛程导入数据库，并记录导入标记；重复启动不重复导入，也不会覆盖后续修改。2026-11-22 岭南学院对数学学院按用户确认录为 0:0、已结束，其余比赛按原赛程导入，不推测结果。今后首页和比赛中心都从数据库读取赛程。

## 上线前检查与回退

1. 对线上实际代码做差异检查，保护服务器和其他协作者后续改动。
2. 在维护窗口前备份线上代码及 SQLite 数据库和用户数据，并验证备份可读取；在数据库副本上先运行迁移和检查。
3. 确认目标账号，部署代码后由管理员在比赛详情页为马煜授权；不输出或复制账号密码。
4. 核验赛程和 0:0 比分、权限、评分与反思功能，检查手机和电脑页面及服务日志。
5. 如果迁移或验收失败，停用新版本、恢复对应的代码和迁移前数据备份；须考虑上线后产生的新数据，避免覆盖新记录。

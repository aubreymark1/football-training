# 账号页训练与比赛请假变更方案

状态：已于 2026-11-23 部署到线上，线上数据库迁移完成。

## 使用方式

- “账号设置 → 我的请假”分别显示训练和比赛的有效请假次数，并提供按场次提交、修改原因、取消请假及查看个人记录的入口。
- 训练安排仍由队长或管理员在“球队 → 集体训练”逐场创建；每周训练计划中的集合时间是文字，不会自动创建场次。比赛使用比赛中心已有赛程。同一周的训练和比赛各有独立请假记录。
- 两类请假均按各自开始时间提前 72 小时判断；逾期仍可提交，修改原因不改变原提交时间，取消后重新提交按新时间计算。
- 两项计数只包括有效请假，排除本人取消的请假及管理员取消的场次；个人历史列表最多展示各类最近 50 条，计数不受展示条数限制。
- 队长或管理员可在比赛详情的“比赛请假与出勤”查看名单及原因；比赛标记为结束后才可确认实际出勤，逾期请假且确认缺席记为旷赛。比赛请假功能启用前的比赛不追溯旷赛。原训练出勤逻辑保持不变。
- 请假原因仅本人、队长和管理员可见。已有有效请假时，不能直接更改训练开始时间或比赛日期、时间；需要取消原场次后重新创建，原请假不会自动转移。

## 数据结构与迁移

- 原 `training_sessions`、`training_leave_requests`、`training_attendance` 原样保留，账号页直接读取既有训练请假记录。
- 新增 `match_leave_requests`：每人每场比赛一条状态记录，保存请假原因、提交时间、截止时间快照、是否按时及有效或取消状态。
- 新增 `match_attendance`：每人每场比赛的队长确认出勤、确认人和确认时间。
- `app_settings` 记录比赛请假功能启用时间，防止对上线前的历史比赛追溯旷赛；不会批量创建请假或出勤记录，不自动扣积分。
- 上线前备份代码、SQLite 和上传数据并校验；先在真实数据库副本上核对原训练请假及其他记录不变，再发布并检查权限、计数和服务。若服务恢复后已有新数据，回退前需评估，不能直接覆盖新数据。
